# Сборум · Sborum

**Собирай людей на встречи прямо в Telegram — с понятным ответом, хватает ли участников.**

Сборум — бот для разовых и регулярных мероприятий, которым нужно минимальное число участников: волейбольной тренировки, настольной игры, репетиции или встречи клуба. Организатор задаёт расписание и кворум, бот публикует напоминание с опросом, а участники отмечают свои планы в привычном чате.

Кворум — это количество ответов «Буду», необходимое для встречи. Сборум показывает, сколько человек подтвердили участие и скольких ещё не хватает. Организатору не нужно каждый раз создавать одинаковый опрос и вручную пересчитывать ответы.

## Для организатора и участников

- **Организатору:** один раз настроить регулярную встречу, управлять мероприятиями через меню и проверять сбор командой `/status`.
- **Участникам:** выбрать «Буду», «Не смогу» или «Пока не знаю» в Telegram-опросе; пока он открыт, ответ можно изменить или отозвать.
- **Сообществу:** вести несколько мероприятий в одной группе, включая публикацию в отдельных topics.

Сборум разворачивается как собственный бот с токеном от BotFather. Участникам достаточно Telegram; отдельный аккаунт в Sborum не нужен. Известные ограничения обработки ответов и доставки уведомлений описаны [ниже](#ограничения-текущей-реализации).

## ✨ Что умеет Сборум

| Возможность | Как это работает |
|---|---|
| **Разовые и регулярные встречи** | Мероприятие на конкретную дату или повторение через заданное число дней — например, каждые 7 дней |
| **Публикация по расписанию** | Выбираешь, за сколько дней до встречи и в какое время отправить напоминание и опрос |
| **Часовой пояс для каждого мероприятия** | Расписание рассчитывается по timezone встречи; её можно выбрать из списка или указать вручную |
| **Три варианта ответа** | Неанонимный опрос с одним выбранным вариантом: «Буду», «Не смогу», «Пока не знаю» |
| **Кворум и статус сбора** | В кворум входят ответы «Буду»; `/status` показывает сохранённые количества по всем трём вариантам и недостающих участников |
| **Сообщения об изменении кворума** | Бот отправляет сообщение, когда порог достигнут или участников снова стало недостаточно; доставка имеет [ограничения](#ограничения-текущей-реализации) |
| **Закрытие голосования** | По заданной длительности или вручную командой `/closepoll`; бот отправляет итоговый статус |
| **Управление через Telegram** | Пошаговое создание, редактирование, пауза и возобновление публикаций, удаление мероприятий — через команды и кнопки |
| **Проверка перед запуском расписания** | `/publish` позволяет отправить тестовый опрос в чат и проверить сценарий на практике |

## 🏐 Пример: еженедельный волейбол

Для игры нужно **6 человек**. Организатор создаёт повторяющееся мероприятие «Волейбол»: первая дата — 24.10.26, интервал — 7 дней, публикация — за день до встречи в 19:00 по `Europe/Moscow`, длительность голосования — 22 часа.

23 октября бот публикует напоминание:

```text
Напоминание о предстоящем мероприятии.
Мероприятие «Волейбол» состоится завтра: 24.10.26.
Минимальный кворум — 6 человек.
Пожалуйста, отметь актуальный вариант в голосовании ниже.
```

Следом — Telegram-опрос:

```text
Кто будет на мероприятии «Волейбол» 24.10.26?

✅ Буду
❌ Не смогу
🤔 Пока не знаю
```

Например, при четырёх подтверждениях, одном отказе и двух неопределившихся `/status` покажет:

```text
Статус «Волейбол» на 24.10.26:
✅ Будут: 4
❌ Не смогут: 1
🤔 Пока не знают: 2

До кворума не хватает: 2.
```

Так видно, сколько участников ещё нужно собрать. В примере использованы вымышленные ответы; формат сообщений соответствует текущему коду.

## Как начать пользоваться

Если своего экземпляра ещё нет, начни с [новой установки в Cloudflare](docs/cloudflare-deploy.md#новая-установка). Для уже настроенного бота:

1. Добавь своего бота в Telegram-группу и обеспечь ему возможность отправлять сообщения и опросы.
2. Администратор чата или настроенный владелец бота запускает `/addevent` и отвечает на вопросы мастера.
3. Укажи дату, время публикации, длительность опроса, timezone и минимальное число участников. Для повторяющегося мероприятия задай интервал в днях.
4. Бот публикует неанонимный опрос; участники выбирают ответ. `/status` показывает сохранённый кворум, `/events` открывает список и настройки мероприятий.

`/publish` отправляет настоящее тестовое голосование в чат — это не dry run.

## Команды Telegram

| Команда | Назначение |
|---|---|
| `/events` | Список мероприятий и доступные настройки |
| `/addevent` | Добавить мероприятие через мастер |
| `/schedule` | Ближайшие активные мероприятия |
| `/status` | Сохранённое состояние кворума |
| `/publish` | Опубликовать тестовое голосование |
| `/closepoll` | Закрыть последнее открытое голосование |
| `/cancel` | Отменить пошаговый ввод |
| `/version` | Версия бота |
| `/chatid` | ID чата и topic |
| `/whoami` | Твой Telegram user ID |
| `/help` | Краткая справка |

Управление мероприятиями доступно администраторам чата и пользователю из `OWNER_USER_ID`. Владелец получает права управления во всех чатах бота: при собственной установке обязательно проверь этот ID.

## Локальная проверка исходников

Нужны Git, Node.js **22+** и npm; CI использует Node.js 22. Хотя `package.json` приложения допускает Node.js 20+, зафиксированный в lockfile Wrangler требует 22+. Для проверки кода токен Telegram и доступ к Cloudflare не требуются.

```bash
git clone https://github.com/ipastin/sborum-bot.git
cd sborum-bot
npm ci
npm run check
npm test
```

`check` проверяет синтаксис JavaScript, `test` запускает тесты через `node --test`. Запуск Worker и проверка настоящих Telegram-операций — отдельные шаги из runbook; используй для них отдельного тестового бота и базу.

## Cloudflare: установка и обновление

Бот работает на **Cloudflare Workers + D1**: Telegram доставляет updates через webhook, Cron Trigger проверяет расписание каждую минуту. VPS-инструкции относятся к историческому способу запуска.

Выбери сценарий в [Cloudflare runbook](docs/cloudflare-deploy.md):

- **Обновление действующего Worker:** проверить account/database, миграции и секреты; существующий webhook обычно менять не требуется.
- **Новая установка:** создать собственные Worker и D1, заменить уже заполненные значения конфигурации и зарегистрировать webhook.
- **Условный legacy-перенос с VPS:** только при наличии проверенного источника данных, с остановкой writers и отдельным планом переключения.

Конфигурация находится в [`wrangler.jsonc`](wrangler.jsonc). В ней уже стоят конкретные `database_id` и `OWNER_USER_ID` — это не шаблон для чужой установки. Секреты `BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` хранятся в Cloudflare, не в Git.

## Ограничения текущей реализации

- Worker возвращает HTTP 200 до завершения обработки update в `waitUntil`. Ошибка фоновой обработки, в том числе D1, сама по себе не заставляет Telegram повторить доставку.
- Порядок и дедупликация `poll_answer` по `update_id` не обеспечены. Поздний старый ответ может изменить более свежий голос; параллельная обработка может повлиять на пересчёт кворума.
- Уведомление о кворуме отправляется после записи состояния. При ошибке Telegram гарантированной повторной отправки уведомления нет.
- [`scripts/set-webhook.mjs`](scripts/set-webhook.mjs) использует `drop_pending_updates: true` и при установке, и при удалении webhook. Не используй его для переключения с сохранением очереди; соответствующие API-команды и ограничения описаны в runbook.

Сохранение pending updates на стороне Telegram не гарантирует успешную обработку каждого ответа приложением.
